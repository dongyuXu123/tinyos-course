# Mini-GRUB 课程文档模板（精讲与规划）

> 本文件定义 Mini-GRUB 课程每课文档的统一结构与质量标准。已实现课为**精讲文档**
> （对应 TinyOS 主线 `docs/lesson-lecture-template.md` 的可执行课变体），设计中的课
> 为**课程规划文档**。**所有代码引用必须来自该课实际源码，禁止编造代码、标识符或
> 输出串。**

## 一、精讲文档（已实现课，250–500 行）

### `# Lesson BNN: <标题> — 精讲文档`

顶部信息块（引用块 `>`）：课号、本课主题、课程位置（第几阶段）、前置课程、
后续课程、一句话目标。

### `## 1. 课程定位（Mission）`

- 一句话目标（学完本课你能……）
- 在课程中的位置（阶段、前后课、为何在此位置）
- 前置知识清单（至少 3 项）
- 本课交付（可见结果：QEMU VGA 画面 / 新数据结构 / 新命令）

### `## 2. 核心概念精讲`

- 每个新概念一节（`## 2.1`、`## 2.2`……），包含：定义 → 为什么需要（动机）→
  工作机制 → 示意图/例子。能画图就画图（ASCII/mermaid）。

### `## 3. 源码精讲`（本课最长章节）

#### `### 3.1 文件清单与职责`

表格：`文件 | 职责 | 本课增量（相对上一课）`，所有文件都要列。

#### `### 3.2 <每个源文件一节>`

1. 结构/宏/常量/全局变量精讲（表格或列表）。
2. 函数精讲：签名、输入输出、算法步骤、边界/错误处理、设计取舍；逐行引代码并加
   中文注释。

#### `### 3.3 构建管线`

Makefile 目标、汇编/编译/链接 flags、链接脚本、镜像拼装步骤（对比上一课的新步骤）。

#### `### 3.4 主控制流`

从 `_start`/入口到输出的一整条调用链。

### `## 4. 数据流与运行逻辑`

完整的「上电 → 指令 → 数据 → VGA 输出」路径，直到具体输出格式串。

### `## 5. 构建、运行与验证`

- 依赖（本课特有的）
- `make clean && make -j"$(nproc)"`、`make check`、`make run`（QEMU 窗口）
- 自动化：`bootloader-course/scripts/validate-course.sh bNN check|qemu`
- 期望输出**逐字引用源码中的字符串**、成功判据

### `## 6. 调试地图`

表格 `现象 | 原因 | 检查方法`，至少 5 行，与本课代码绑定。

### `## 7. 与 GNU GRUB 源码对照`

本课实现 vs GRUB 对应文件（`$GRUB_SRC` 路径），指出复刻了什么、简化了什么、为什么；
引用研读支线对应课（0.x）与 [`docs/grub-implementation-guide.md`](../docs/grub-implementation-guide.md)。

### `## 8. 思考题与练习`

3–5 题，覆盖概念/源码定位/动手/Linux 对照类型。

### `## 9. 本课小结与下一课预告`

5–8 句小结 + 下一课链接。

## 二、课程规划文档（设计中课，120–200 行）

### `# Lesson BNN: <标题> — 课程规划（设计中）`

顶部信息块：课号、主题、课程位置、前置、后续、一句话目标；**明确标注「本课当前
为设计文档，代码待实现」**。

### `## 1. 课程定位（Mission）`

一句话目标、位置、前置知识清单、预期交付（QEMU VGA 可见结果）。

### `## 2. 核心概念要点`

概念清单与每个概念的动机/机制要点（不要求完整精讲，但要列出教学关键点）。

### `## 3. 对照 GRUB 源码`

`$GRUB_SRC` 中的目标文件/符号、研读支线对应课、复刻范围与简化边界。

### `## 4. 产物与验证标准`

预期文件清单、Makefile 目标、`make check` 断言、QEMU 冒烟与 VGA 文本 marker
（自动化脚本按 marker 校验）。

### `## 5. 设计要点与风险`

实现路线、关键数据结构、与前后课的接口、已知风险/开放问题。

### `## 6. 后续课程预告`

下一课链接与衔接点。

## 三、通用规则

- 全文中文；代码引用逐字来自该课实际源码；输出串逐字来自源码字符串。
- 必须链接前置/后续课 README 与共享文档。
- 只允许写 README.md；不修改/删除源码、Makefile、链接脚本或 build 产物。
- 设计中课保留稳定目录命名（`bNN-stable`），但 README 首部必须带「设计中」标记，
  避免与已实现课混淆。
