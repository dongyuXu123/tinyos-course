# 课程精讲文档模板（Lesson Lecture Template）

> 本文件定义「每课精讲文档」的统一结构与质量标准。所有 `lessons/lesson-XX-stable/README.md`
> 必须按此结构重写，且篇幅必须显著超过被替换的旧 README：
> 可执行课 250–500 行，文档课（00、0.1–0.10）150–300 行。
> **所有代码引用必须来自该课实际源码，禁止编造代码、标识符或输出串。**

## 一、统一结构（每个标题都必须出现）

### `# Lesson XX: <标题> — 精讲文档`

文件顶部信息块（引用块 `>`），包含：课号、本课主题、课程主线位置（第几阶段）、
前置课程、后续课程、本课一句话目标。

### `## 1. 课程定位（Mission）`

- 一句话目标（学完本课你能……）
- 在课程主线中的位置（属于哪个阶段、前后课是谁、为何在此位置）
- 前置知识清单（至少 3 项：学本课之前必须掌握什么）
- 本课交付（可见结果：VGA 画面 / 新命令 / 新数据结构）

### `## 2. 核心概念精讲`

- 每个本课新引入的概念一节（`## 2.1`、`## 2.2`……）
- 每个概念必须包含：定义 → 为什么需要（动机）→ 工作机制 → 示意图或例子
- 从初学者出发：先给直觉，再给准确定义；能画图就画图（ASCII/mermaid）

### `## 3. 源码精讲`（本课最长的章节）

#### `### 3.1 文件清单与职责`

表格：`文件 | 职责 | 本课增量（相对上一课）`。所有文件都要列，包括未变化的
`grub.cfg` 等，并说明「未变化」或「微小变化」。

#### `### 3.2 <每个源文件一节>`

每个文件按以下方式精讲：

1. **结构/宏/常量/全局变量精讲**：逐个列出并解释含义（表格或列表）。
2. **函数精讲**：每个关键函数一个条目，必须包含——
   - 签名与职责；
   - 输入输出与涉及的数据结构；
   - 算法步骤（编号列表）；
   - 边界检查与错误处理；
   - 为什么这样设计（对照硬件规范 / Linux 源码 / 上一课）。
3. **代码引用**：引用实际代码片段，并在代码块内/后加中文逐行注释。
   代码必须与源码逐字一致（允许省略与主题无关的既有重复代码，但要说明省略了什么）。

#### `### 3.3 构建管线（Makefile / linker）`

- 每个 Makefile 目标的含义；
- 新增编译标志 / 链接脚本的作用（`-m32`、`-m64`、`-ffreestanding`、`-mno-red-zone`、
  `KEEP()`、`ALIGN` 等，按实际出现情况写）；
- 相对上一课新增了哪些构建步骤。

#### `### 3.4 主控制流`

- 从 `_start` / `kernel_main64_binary` 到本课功能的调用链（文字流程或 mermaid 图）。

### `## 4. 数据流与运行逻辑`

- 串起「启动 → 命令/事件 → 数据处理 → VGA 输出」的完整路径；
- 具体到：输入什么命令 → 进入哪个 `exec64` 分支 → 调用哪个函数 →
  打印哪个输出格式串 → 屏幕上显示什么。

### `## 5. 构建、运行与验证`

- 依赖说明（如本课需要额外工具）；
- 构建命令（必须与 Makefile 一致）：`make clean && make -j"$(nproc)"`、`make check`；
- 运行命令：`make run`，注明「成功画面在 QEMU 图形窗口，勿加 `-display none`」；
- 验证步骤：输入哪些命令，预期输出什么——**输出串必须从源码中逐字抄录**；
- 如何判断成功（含 GUI 课程可引用 `scripts/qemu-vga-check.sh` 专项流程）。

### `## 6. 调试地图`

表格：`现象 | 原因 | 检查方法`，至少 5 行，每条必须与本课代码相关。
保留并扩充旧 README 中的调试条目。

### `## 7. 与 Linux 源码对照`（如 README 提及）

- 每个对照点：TinyOS 教学模型做了什么 vs Linux 对应实现（给出 Linux 文件路径）；
- 标注权威来源（Intel SDM / Multiboot2 规范 / GNU GRUB）；
- 说明「教学模型简化了什么」。

### `## 8. 思考题与练习`

- 3–5 题，覆盖四类：概念理解、源码定位、动手实验（改代码再验证）、Linux 对照。

### `## 9. 本课小结与下一课预告`

- 5–8 句话总结本课学到了什么；
- 下一课要做什么、与本课的衔接点。

## 二、文档课（00、0.1–0.10）专用调整

文档课没有内核源码，把「## 3. 源码精讲」替换为「## 3. 机制精讲与观察方法」：
- 无源码可引用时，精讲本课的**对象**（如 GRUB 源码树、MBI 布局、grub.cfg 语法、
  Multiboot2 header 字段），逐字段/逐组件讲解；
- 给出**只读观察命令**（`readelf`、`grub-file`、`xorriso`、`grep -R` 等）以及
  每条命令的预期输出解读；
- 保留「## 5 观察与验证」「## 6 调试地图」「## 8 思考题与练习」等结构。

## 三、质量标准（违反即不合格）

1. 源码精讲必须引用实际代码并逐行/逐块注释，禁止泛泛而谈；
2. 每个关键函数至少 3 行实质分析（算法/边界/动机）；
3. 验证输出串必须从源码中逐字抄录，不得杜撰；
4. 不得删除旧 README 中的验证记录、调试地图、权威来源边界（保留并扩充）；
5. 篇幅：可执行课 250–500 行；文档课 150–300 行；
6. 全程中文；代码标识符、命令、输出保留原文；
7. 只写 `README.md`，**不得修改或删除任何源码、Makefile、linker、build 产物**；
8. 文件开头必须与上一课/下一课 README 建立相对链接（`../lesson-XX-stable/README.md`），
   方便连续学习。
